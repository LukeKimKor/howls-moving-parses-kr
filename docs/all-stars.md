# All Stars 표시와 집계 범위

## 구현

- 종합 요약은 캐릭터 13행의 통합 표에서 영웅·신화를 나란히 비교한다. 각 난이도에 최고/중앙값 백분위·종합 점수·WCL 순위가 있다. 피해 지표 버튼은 전체 피해/우두머리 피해를 전환하며 힐러는 치유량을 유지한다. 공식 패치명 중 최신 버전을 기본 선택하고 과거 버전은 선택기와 ‘전체 패치 기록’에서 보존한다. 본문 16px, 오른쪽 목차, 선택한 A 색상과 Pretendard 계열 폰트는 유지한다. [통합 요약 측정](compact-summary.md)을 참고한다.
- 요약의 All Stars 기본 기준은 공격 전문화 `dps`, 치유 전문화 `hps`이다. 공격 전문화는 명시적인 버튼으로 `bossdps`로도 전환할 수 있다. 각 전문화·난이도·선택한 패치의 점수·순위 쌍을 그대로 표시하며 해당 패치 값이 없으면 과거 값으로 대체하지 않는다. 다른 전문화·난이도·지표·패치의 값을 합산하거나 가장 큰 점수를 임의 선택하지 않는다. 백분위는 기존 WCL 요약값이며 점수 패치 선택으로 재계산하지 않는다.
- 데스크톱과 모바일의 각 성적표에 공격대 종합 점수·순위 카드를 노출한다. 보스 표의 점수·순위는 별도 강조한다. 모바일의 보스 상세와 전체 캐릭터 요약에도 유지한다.
- 미확인 표 셀은 시각적으로 비우고 접근성 레이블을 제공한다. 실제 0은 `0`으로 구분한다. 파멸과 포식은 별도 전문화이며 주 전문화를 정하지 않는다.

## 실제 캐시 조사

원본: 공개 실행 #8의 실제 스냅샷, `generatedAt=2026-10-17T00:01:59.285Z`. 이번 변경은 수집을 실행하지 않는다.

- 공격대 53, The Venomous Abyss. 13명·14전문화·52개 지표/난이도 응답·520개 보스 행을 보존한다.
- 현재 `zoneRankings` 호출은 `zoneID`, `difficulty`, `metric`, `specName`을 지정하고 `partition`과 `timeframe`을 생략한다. 이를 ‘전체 패치’ 또는 ‘현재 패치’ 요청이라고 단정하지 않는다.
- 응답의 상위 `partition`은 모두 -1이다. 요약 `allStars[]`의 개별 점수·순위에는 구분 ID 1 또는 2가 있다. 이름은 캐시에 없다. 배열의 순서나 점수 크기로 패치를 추론하지 않는다.
- 예: 오렌지크림피자·비전·영웅·전체 피해는 ID 2 점수 897.969/순위 16, ID 1 점수 1017.71/순위 308이다. 둘은 각각 한 쌍이며 합계가 아니다. 화면 소수 둘째 자리 반올림은 표시 형식일 뿐 원본 숫자는 그대로 둔다.
- 보스 행의 `allStarPoints`와 `allStarRank`는 같은 원본 행에서 온 쌍이다. 그러나 행별 All Stars의 구분 ID는 기존 매퍼가 보존하지 않아, 보스 점수의 패치명은 확인할 수 없다. 이를 요약의 특정 패치 값과 동일하다고 주장하지 않는다.
- 보존된 순위는 WCL `rank`다. `regionRank`/`serverRank`는 현재 스냅샷에 없어 KR 순위나 서버 순위라고 바꾸어 표시하지 않는다.

## 패치 이름 확인 상태

공식 페이지/문서는 직접 열기에서 HTTP 403이 반환되어 우회하지 않았다. 이후 승인된 기존 Secrets 경로의 정상 API 메타 실행 결과가 공개 스냅샷에 반영되었다. `checkedAt=2026-10-17T02:54:46.405Z`의 공격대 53 공식 응답은 **ID 1=12.1, ID 2=12.1.5**다. 이번 통합 요약 변경에서는 이 공개 캐시만 읽었으며 게임 API를 호출하지 않았다.

UI는 공식 API에서 저장한 `raidPatchMetadata.partitions`의 공격대 ID와 각 점수의 구분 ID가 모두 일치할 때만 실제 이름을 표시한다. 하드코딩한 패치 매핑은 없다. 데이터가 없거나 구간이 목록에 없으면 `패치명 미확인`을 표시한다. -1을 `전체 패치`로 추론하지 않는다.

## 승인된 API 경로로 이름 수집

기존 GitHub Secrets와 기존 OAuth/전송/예산 정책을 사용하는 `patches` 모드를 추가했다. 로컬에서 인증하거나 비밀 값을 읽어 실행하지 않았다. 다음 정상 워크플로에서 실행할 수 있다.

1. 기존 공개 캐시를 복원한다. 공격대 ID는 캐시의 `raid.id`를 그대로 사용한다.
2. 스키마 쿼리 1회로 `Zone.partitions`의 실제 반환 타입과 `Partition.id/name` 필드, `Character.zoneRankings`의 `partition/timeframe` 인자 설명·기본값을 확인한다. 반환 타입명이 다르면 그 정확한 이름의 타입 확인만 1회 추가한다. 임의의 필드나 패치 버전으로 재시도하지 않는다.
3. 유효한 포인트 응답과 기존 20% 안전 여유를 확인하고 `worldData { zone(id: $zoneId) { id name partitions { id name } } }`를 1회 조회한다. 예산은 기존 쿼리에 `collectorBudget: rateLimitData`로 함께 요청하므로 별도 예산 쿼리를 만들지 않는다.
4. 영역 ID, 이름과 중복 ID를 검증한 뒤 메타데이터만 기존 스냅샷에 더한다. 캐릭터·전문화 표본·기록·경고·로그 수집 시각은 재수집하거나 갱신하지 않는다. 빌드 해시만 새로 만든다.

GitHub Actions의 **Refresh Data & Deploy → Run workflow**에서 `mode=patches`, `force_refresh=false`로 1회 실행한다. 기본적으로 GraphQL 2회(스키마 1 + 공격대 메타 1)와 기존 OAuth 토큰 교환만 필요하다. 스키마·예산·응답 검증 실패 시 스냅샷을 쓰기 전에 중단한다. 기존 Secrets가 없으면 Raider.IO 수집으로 대체하지 않는다. 수집 결과와 인자 설명 원문·기본값·실제 예산은 비밀 값 없이 실행 로그와 Step Summary에 기록한다.

일반 `characters` 실행에서도 인증·영역 초기화가 필요할 때 패치 정보가 없거나 24시간이 지나면 같은 검증으로 갱신한다. `cache` 모드는 새 API 없이 이미 저장된 매핑을 보존한다. 정상 실행에서 받은 `Character.zoneRankings.partition` 설명은 기본적으로 최신 구간을 선택하고 특별한 인자 값 -1은 모든 구간을 조회한다는 내용이며, `defaultValue`는 `0`이었다. 인자 설명과 스냅샷 JSON의 상위 `partition` 속성을 무조건 같은 뜻으로 간주하지 않는다. UI의 점수·순위는 개별 All Stars 항목의 정확한 ID에만 공식 이름을 붙인다.

## 공식 의미 근거

- [WCL/Archon Rankings and Parses 안내](https://www.archon.gg/wow/articles/help/rankings-and-parses): 밸런스 변경 시 비교 구간을 나눌 수 있으며 All Stars 점수와 순위는 WCL 계산값이다. 직접 페이지 열기는 403이어서 공개 검색 색인으로 설명을 확인했다.
- [WCL 담당자 Vel의 All Stars 설명](https://forums.combatlogforums.com/t/how-is-the-overall-raid-allstar-points-computed/14340/4): 여러 구간의 All Stars 점수를 합산하지 않는다는 공식 담당자의 설명. 해당 글의 10.1.5 사례는 현재 공격대 53의 ID 매핑 근거로 사용하지 않는다.

테스트의 합성 데이터는 0/빈 값/전문화 격리를 검증하기 위한 것으로 실제 로그 파일에 저장하지 않는다.
