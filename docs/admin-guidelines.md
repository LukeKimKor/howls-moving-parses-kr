# 사이트 관리 지침

와우 대시보드(`howls-moving-parses-kr`)를 관리할 때 따르는 기준이다. 사이트 주인과 정한 내용을 기록하며, 결정이 바뀌면 이 문서부터 고친다.

## 목적

1. 내 캐릭터 13개의 **Warcraft Logs 점수**를 한 번에 본다.
2. 내 캐릭터 13개의 **Raider.IO 쐐기 점수**를 한 번에 본다.
3. 전체 캐릭터 상황을 **한눈에 보는 종합 현황판**을 첫 화면에 둔다.
4. **깔끔하고 정돈된 다크 대시보드** 디자인을 유지한다.

## 화면 구성 (결정됨)

탭 세 개로 나눈다. 주소 끝의 `#overview`, `#raid`, `#mplus`로 각 탭에 바로 들어갈 수 있다.

| 탭 | 내용 | 출처 |
|---|---|---|
| 종합 현황 (기본) | 요약 카드 5개 + 딜러/힐러/탱커 표. 전문화별 한 줄: 템렙, 쐐기 점수, 영웅·신화 각각 처치·최고·중앙·All Stars 점수·순위 | WCL + Raider.IO |
| 레이드 로그 | 역할별 레이드 요약표 + 전문화별 보스 카드(보스 × 영웅/신화 최고·중앙·처치·초당 수치), 오른쪽 목차 | WCL |
| 쐐기 | 점수·순위·템렙과 던전별 최고 단수(시간 내/초과) | Raider.IO |

캐릭터 이름을 누르면 기존 상세 화면(쐐기 기록·장비·특성·메타)으로 가고, "대시보드로 돌아가기"는 보던 탭으로 돌아온다.

- 종합 현황판에서 반드시 보이는 지표: **레이드 처치 수(영웅·신화), WCL 최고·중앙값 %, WCL All Stars 점수·순위, Raider.IO 쐐기 점수, 아이템 레벨**.
- **한 칸에는 값 하나.** 최고/중앙처럼 두 값을 한 칸에 넣지 않는다. 난이도는 열 묶음(영웅 / 신화)으로 나누고, 그 아래 처치·최고·중앙·점수·순위를 각각 한 열로 둔다.
- **행 = 캐릭터 × 전문화.** 여러 전문화를 추적하는 캐릭터는 전문화마다 별도 행이다. 쐐기 점수·템렙은 캐릭터 값이라 각 행에 같은 값이 나온다.
- **역할별로 표를 나눈다.** 딜러 / 힐러 / 탱커 순서. 해당 역할이 없으면 빈 상태 안내를 보여준다(지금은 탱커 없음).
- 레이드 피해 지표는 전체 피해/우두머리 피해를 전환할 수 있고, 힐러(보존 기원사, 신성 성기사)는 항상 치유량이다. All Stars는 패치를 선택할 수 있고 기본값은 최신 패치다.
- **처치 열은 난이도 묶음 맨 앞**에 둔다. 백분위가 몇 마리 보스에서 나온 값인지(표본 크기) 먼저 보이게 하기 위해서다. 표기는 `6/10` + 보스 1마리당 1칸 막대, 전체 처치는 숫자를 난이도 색(보라/주황)으로. 값은 레이드 로그 보스 카드와 같은 계산(`raid-overview.ts`의 `specKillProgress`)을 쓴다. 최고·중앙은 기존처럼 소수점 한 자리 %(`97.3%`)로 표시한다.
- 정렬: 등록 순(기본), 쐐기 점수, 템렙, 난이도별 처치 수·최고·중앙·All Stars 점수. 값이 없는 행은 항상 맨 아래. 열 제목을 눌러도 정렬된다.
- 캐릭터 열은 좁게 유지한다(표 너비의 약 14%). WCL/RIO 바로가기는 이름 아래 작은 링크로 둔다.

## 캐릭터 설정 (결정됨)

- 캐릭터 목록은 `characters.config.json`이 유일한 기준이다. 추가·삭제·전문화 변경은 이 파일만 고친다.
- **오렌지크림피자**: 비전(주 전문화) + 냉기(부 전문화, 2026-10-19 추가). 냉기로 레이드를 돈 기록이 있어서 별도 행으로 추적한다.
- **앙귀태**: 파멸·포식 두 전문화를 **동등하게** 표시한다. 주 전문화를 정하지 않으며(`mainSpecPending: true`, 두 전문화 모두 `tracked`), 어느 화면에서도 두 값을 평균 내거나 하나를 숨기지 않는다.

## 데이터 원칙

- **없는 값을 지어내지 않는다.** 샘플·추정 값을 넣지 않고, 빈칸이나 "기록 없음"으로 둔다.
- **"기록 없음"과 "조회 실패"를 구분한다.** 수집은 성공했지만 로그가 없으면 "기록 없음", 실패·일부 실패는 "조회 실패", 아직 조회하지 않았으면 "미조회".
- 갱신 주기(TTL) 때문에 건너뛴 구간은 상태가 `skipped`여도 이전에 수집한 실제 보스 행을 갖고 있다. 이때는 "미조회"가 아니라 그 데이터대로(처치 `0/10`, 백분위 "기록 없음") 표시한다. 보스 행이 전부 `unavailable`일 때만 "미조회"다.
- **WCL 레이드 값은 전문화별로 집계한다.** 각 행은 그 전문화로 기록한 처치만 포함하므로, WCL 캐릭터 페이지의 기본 화면(All Specs)과 숫자가 다를 수 있다. 다른 전문화로 레이드를 돌았다면 그 전문화를 설정에 추가해 별도 행으로 본다. 표의 WCL 링크는 해당 전문화 필터로 열어 숫자가 일치하게 한다.
- 쐐기 점수·아이템 레벨은 캐릭터 전체 값(Raider.IO)이고, WCL 백분위는 전문화별 값이다. 둘을 섞어 계산하지 않는다.
- WCL 요청 한도와 갱신 일정은 [refresh-policy.md](refresh-policy.md)를 따른다. 한도 초과 뒤에는 재시도를 반복하지 않는다.
- API 키(WCL Client ID/Secret)는 GitHub Secrets에만 둔다. 채팅·코드·문서에 적지 않는다.

## 디자인 원칙

- 다크 배경(`#0b0f16`)에 패널(`#111824`), 얇은 테두리(`#222e40`). 토큰은 `src/dashboard.css` 맨 위 `.dash`에 모여 있다.
- 색은 의미가 있을 때만 쓴다: **직업색 = 캐릭터 구분**, **WCL 백분위 색 = 레이드 성적**, **Raider.IO 점수 색 = 쐐기 성적**, 보라 = 영웅, 주황 = 신화, 초록 = 시간 내 완료.
- **All Stars 색은 WCL과 같게**: 점수는 WCL 고정 점수색(`#d1fa99`), 순위는 WCL이 주는 순위 백분위(rankPercent)를 백분위 색 구간(회색/초록/파랑/보라/주황/분홍/금색)에 적용한다. 백분위가 없는 예전 데이터는 기본 글자색으로 둔다.
- **템렙 색 = 한밤 2시즌 문장 졸업 구간** (`src/lib/roster.ts`의 `ILVL_TIERS`): 331+ 신화 문장 졸업(주황), 321+ 영웅 문장 졸업(보라), 308+ 챔피언 문장 졸업(파랑), 292+ 챔피언 트랙(초록), 그 아래 회색. 시즌이 바뀌면 이 표만 고친다.
- **캐릭터 행 배경 = 직업색을 아주 옅게**: 행 전체 5%, 캐릭터 칸은 13%에서 오른쪽으로 옅어지는 그라데이션, 마우스를 올리면 9%. 더 진하게 하지 않는다(가독성·명암 대비 유지). `DashParts.tsx`의 `classRow()`로 적용한다.
- 쐐기 점수 칸에는 점수만 표시한다. Raider.IO 등급 이름(불멸·에테르 등)은 쓰지 않는다.
- 숫자는 고정폭 숫자(tabular-nums), 오른쪽 정렬. 영어 직업명 대신 한국어 라벨과 직업색 이름.
- 모바일(767px 이하)에서는 표가 행별 카드로 바뀐다. 가로 스크롤이 생기면 안 된다.
- 세 탭은 같은 부품(`DashParts.tsx`: 캐릭터 칸, 전문화 칩, 백분위 칸, 정렬 제목, 역할 제목, 선택 버튼)을 쓴다. 새 표도 이 부품으로 만든다.
- 클릭 가능한 요소는 최소 24×24px, 링크의 화면낭독기 이름에는 보이는 글자(WCL, RIO 등)가 들어가야 한다.
- 폰트는 기존 Pretendard 계열을 유지한다.
- **화면에 새 한글 문구를 넣으면 코어 폰트를 다시 만든다.** 첫 화면 속도를 위해 UI에 쓰인 글자만 담은 작은 폰트(`public/fonts/HmpDashboardSansCore.woff2`)를 미리 불러온다. 여기에 없는 글자가 생기면 추가 폰트 파일을 내려받느라 첫 표시가 느려지고 Lighthouse 성능 기준(90)에 걸린다. 공식 Pretendard 1.3.9 원본으로 `scripts/fonts/build-core.py`를 실행해 다시 만든다([performance.md](performance.md)).
- Raider.IO 점수 색은 밝은 배경용이라, 어두운 배경의 글자에는 `readableOnDark()`로 밝게 섞어 쓴다(명암 대비 기준 충족). 막대 그래프는 원래 색을 쓴다.

## 변경 절차

1. 변경 전 이 문서와 관련 문서(`docs/`)를 확인한다.
2. `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`를 모두 통과시킨다. 배포 전 수동 실행에는 Lighthouse 기준(성능 90, 접근성 95, 권장사항 100)이 있어, 화면을 바꾸면 로컬에서도 같은 측정을 해 본다. 화면 변경은 데스크톱(1440px)과 모바일(390px) 화면을 직접 확인한다.
3. 실제 데이터 없이 화면을 볼 때 쓰는 임시 스냅샷은 커밋하지 않는다(`src/data/snapshot.json`은 git 제외 대상).
4. 커밋 메시지에는 무엇을, 왜 바꿨는지 적는다.
