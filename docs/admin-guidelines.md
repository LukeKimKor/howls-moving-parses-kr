# 사이트 관리 지침

와우 대시보드(`howls-moving-parses-kr`)를 관리할 때 따르는 기준이다. 사이트 주인과 정한 내용을 기록하며, 결정이 바뀌면 이 문서부터 고친다.

## 목적

1. 내 캐릭터 13개의 **Warcraft Logs 점수**를 한 번에 본다.
2. 내 캐릭터 13개의 **Raider.IO 쐐기 점수**를 한 번에 본다.
3. 전체 캐릭터 상황을 **한눈에 보는 종합 현황판**을 첫 화면에 둔다.
4. **깔끔하고 정돈된 다크 대시보드** 디자인을 유지한다.

## 화면 구성 (결정됨)

탭 세 개로 나눈다. 주소 끝의 `#overview`, `#raid`, `#mplus`로 각 탭에 바로 들어갈 수 있다.

| 탭 | 내용 | 출처 |
|---|---|---|
| 종합 현황 (기본) | 요약 카드 5개 + 캐릭터별 한 줄: 아이템 레벨, 쐐기 점수(서버 순위), 영웅·신화 최고/중앙값 백분위 | WCL + Raider.IO |
| 레이드 로그 | 기존 영웅·신화 종합 요약표와 캐릭터별 보스 표, 오른쪽 목차 | WCL |
| 쐐기 | 점수·순위·템렙과 던전별 최고 단수(시간 내/초과) | Raider.IO |

캐릭터 이름을 누르면 기존 상세 화면(쐐기 기록·장비·특성·메타)으로 가고, "대시보드로 돌아가기"는 보던 탭으로 돌아온다.

- 종합 현황판에서 캐릭터별로 반드시 보이는 지표: **WCL 최고/중앙값 %, Raider.IO 쐐기 점수, 아이템 레벨**.
- 레이드 피해 지표는 전체 피해/우두머리 피해를 전환할 수 있고, 힐러(보존 기원사, 신성 성기사)는 항상 치유량이다.
- 정렬: 등록 순(기본), 쐐기 점수, 아이템 레벨, 영웅 최고 %, 신화 최고 %. 값이 없는 캐릭터는 항상 맨 아래.

## 캐릭터 설정 (결정됨)

- 캐릭터 목록은 `characters.config.json`이 유일한 기준이다. 추가·삭제·전문화 변경은 이 파일만 고친다.
- **앙귀태**: 파멸·포식 두 전문화를 **동등하게** 표시한다. 주 전문화를 정하지 않으며(`mainSpecPending: true`, 두 전문화 모두 `tracked`), 어느 화면에서도 두 값을 평균 내거나 하나를 숨기지 않는다.

## 데이터 원칙

- **없는 값을 지어내지 않는다.** 샘플·추정 값을 넣지 않고, 빈칸이나 "기록 없음"으로 둔다.
- **"기록 없음"과 "조회 실패"를 구분한다.** 수집은 성공했지만 로그가 없으면 "기록 없음", 실패·일부 실패는 "조회 실패", 아직 조회하지 않았으면 "미조회".
- 쐐기 점수·아이템 레벨은 캐릭터 전체 값(Raider.IO)이고, WCL 백분위는 전문화별 값이다. 둘을 섞어 계산하지 않는다.
- WCL 요청 한도와 갱신 일정은 [refresh-policy.md](refresh-policy.md)를 따른다. 한도 초과 뒤에는 재시도를 반복하지 않는다.
- API 키(WCL Client ID/Secret)는 GitHub Secrets에만 둔다. 채팅·코드·문서에 적지 않는다.

## 디자인 원칙

- 다크 배경(`#0b0f16`)에 패널(`#111824`), 얇은 테두리(`#222e40`). 토큰은 `src/dashboard.css` 맨 위 `.dash`에 모여 있다.
- 색은 의미가 있을 때만 쓴다: **직업색 = 캐릭터 구분**, **WCL 백분위 색 = 레이드 성적**, **Raider.IO 점수 색 = 쐐기 성적**, 보라 = 영웅, 주황 = 신화, 초록 = 시간 내 완료.
- 숫자는 고정폭 숫자(tabular-nums), 오른쪽 정렬. 영어 직업명 대신 한국어 라벨과 직업색 이름.
- 모바일(767px 이하)에서는 표가 캐릭터별 카드로 바뀐다. 가로 스크롤이 생기면 안 된다.
- 폰트는 기존 Pretendard 계열을 유지한다.

## 변경 절차

1. 변경 전 이 문서와 관련 문서(`docs/`)를 확인한다.
2. `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`를 모두 통과시킨다. 화면 변경은 데스크톱(1440px)과 모바일(390px) 화면을 직접 확인한다.
3. 실제 데이터 없이 화면을 볼 때 쓰는 임시 스냅샷은 커밋하지 않는다(`src/data/snapshot.json`은 git 제외 대상).
4. 커밋 메시지에는 무엇을, 왜 바꿨는지 적는다.
